# تصميم النظام — Sleepee v1.6

## المقصد
منصة تشغيل موحدة تربط تعريف المنتج/الموديل بأمر الإنتاج والدفعة والأرقام التسلسلية والملصق، ثم تتيح سجل الضمان وخدمة العملاء والاستبدال مع تتبع الأحداث والصلاحيات.

## مكونات التنفيذ
- **واجهة:** React + TypeScript + Vite. تعرض سير العمل وتتحقق من المدخلات؛ لا تعتبر إخفاء الزر حماية كافية.
- **هوية:** Supabase Auth، مع `profiles` للحساب و`user_roles` لتعيين دور رسمي بواسطة مسؤول النظام. التسجيل لا يمنح المستخدم دورًا تجاريًا تلقائيًا.
- **طبقة البيانات:** PostgreSQL في Supabase، كيان `models` هو نموذج/منتج النظام، مع جداول مستقلة للتصنيفات والعلامات وخطوط الإنتاج والدفعات والسيريالات.
- **ممر الأمان:** RLS لكل جدول، وRPC لعمليات المجال التي يجب تنفيذها كوحدة واحدة أو التي تمس سجلًا تاريخيًا. التغييرات التي لم يعتمد سيرها تبقى مغلقة.
- **المرفقات:** حاويات تخزين خاصة. سياسة المرفقات المقترحة تقصر الوصول على مرفقات تذكرة خدمة حقيقية.
- **الطباعة:** أوامر وقوالب ولقطات ثابتة من القالب. لا يُسجل `printed` أو سجل نجاح حتى يستكمل رندر معتمد وربط Zebra Browser Print واختبار الطابعة.
- **GitHub / Google AI Studio:** GitHub لحفظ المصدر وتاريخه، وGoogle AI Studio بيئة عمل يدوية منفصلة. لا توجد مزامنة تلقائية أو مسار runtime بينهما.

## تدفق البيانات
1. تجهيز البيانات المرجعية المعتمدة (الفئة، العلامة، الموديل، نوع المنتج، المقاسات).
2. إنشاء أمر إنتاج وبنوده.
3. إنشاء الدفعة ثم توليد السيريالات عبر RPC مع تحقق من كمية وموديل الأمر.
4. اختيار قالب ملصق منشور ونشط يطابق فئة المنتج وحفظ لقطة للقالب داخل أمر الطباعة.
5. تظل عملية الطباعة غير منفذة فعليًا حتى يعتمد محول الطابعة ويختبر؛ أوامر الانتظار لا تمثل إثبات طباعة.
6. تفعيل الضمان عبر `activate_warranty` وحفظ مدة الضمان وتاريخ نهايته كنسخة تاريخية غير قابلة للتعديل.
7. إنشاء/تحديث تذكرة الخدمة والاستبدال عبر RPC وسجل أحداث لا يسمح للواجهة بتحريره مباشرة.

## حدود مهمة
- مدد التشغيل في الجداول الزمنية مرجع تقديري حتى الاعتماد الميداني.
- بنود BOM المتعارضة والمقاسات المتعارضة لا يتم تحويلها إلى بيانات أساسية.
- حالات السيريال/الاستبدال الحساسة تبقى داخل RPC المقترح ومرهونة بمراجعة مالك النظام.
- لا محاسبة أو مشتريات أو HR/Payroll أو ERP مخازن أو POS أو تجارة إلكترونية في نطاق الإصدار.
