# Sleepee — دليل المشروع الموحد

**الإصدار:** 1.6.0-rc.2 — **الحالة:** حزمة تسليم متكاملة للمراجعة، وليست معتمدة للإنتاج.

## ترتيب المرجعية
1. `reference/Sleepee_Single_Source_Of_Truth_v1.0_Portable_Reference.md` هي المرجعية التجارية الحاكمة، محفوظة دون تعديل.
2. مخططات التشغيل والتصنيع وخدمة العملاء وسجل المتطلبات مراجع تفسيرية مساعدة؛ لا تتغلب على المرجعية الحاكمة.
3. الكود يترجم المتطلبات ولا يملك صلاحية إنشاء قاعدة عمل جديدة.
4. SQL تحت `../supabase/proposed-migrations/` مقترح للمراجعة فقط. لا ينفذ تلقائيًا.

## أهم المسارات
- `architecture/`: تصميم النظام ومخططات SVG قابلة للتكبير والطباعة.
- `phases/`: بوابات القبول والحالة الواقعية للمراحل.
- `security/`: مصفوفة الصلاحيات المقترحة بأسماء الأدوار الرسمية.
- `operations/`: تشغيل المشروع والربط اليدوي مع GitHub/Google AI Studio.
- `quality/`: نتائج الفحوص الفعلية والقيود.
- `reference/`: مجموعة صغيرة منتقاة من المراجع الأصلية وملفات الاعتماد.
- `../supabase/proposed-migrations/`: 001 تأسيس مخطط، 002 عقود RPC، 003 سياسات وصلاحيات. تبقى REVIEW ONLY إلى أن تراجع على مخطط حي وتُعتمد.
- `../supabase/verification/`: استعلامات قراءة فقط للتحقق بعد النشر الموافق عليه.
- SQL التاريخي غير مضمّن في حزمة التسليم؛ راجع `operations/LEGACY_SQL_EXCLUSION_AR.md`.

## البدء
```bash
npm ci
npm run verify:release
npm run typecheck
npm run build
npm run dev
```

إعداد البيئة: انسخ `.env.example` إلى `.env.local` وضع قيم Supabase في بيئة التطوير فقط. لا تضف `.env.local` إلى Git.

## حدود صريحة
- لا Firebase.
- `models` هو كيان النموذج/المنتج canonical؛ لا تنشئ جدول `products` ثانٍ.
- لا بيانات تشغيل أو BOM افتراضية.
- لا كتابة مباشرة على تفعيل الضمان أو سجل السيريال أو سجل الطباعة.
- لا توجد طباعة Zebra فعلية معتمدة بعد؛ التنفيذ يفشل بأمان ولا يسجل نجاحًا وهميًا.
- لا تغيير على Supabase الحي في هذه الحزمة.
