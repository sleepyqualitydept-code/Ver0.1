# ضوابط قاعدة البيانات

## الترتيب المقترح
- `001_sleepee_foundation_schema_v1_6_REVIEW_ONLY.sql`: إنشاء جداول النظام الفارغ، القيود، التريجرات، الحاويات الخاصة؛ لا بيانات تشغيل تجريبية.
- `002_sleepee_runtime_contracts_v1_6_REVIEW_ONLY.sql`: RPCs للضمان والتسلسل وخدمة العملاء والاستبدال والتقارير وحالة أمر الطباعة.
- `003_sleepee_authorization_policies_v1_6_REVIEW_ONLY.sql`: grants وRLS وسياسات المرفقات.

هذه الملفات لم تنفذ. لا تضعها تلقائيًا تحت `supabase/migrations` ولا تشغّلها على القاعدة الحية كما هي. الترتيب مجرد مقترح لمشروع تطوير جديد.

## حواجز لا تتغير
- لا `DROP ... CASCADE` ولا `TRUNCATE` ولا حذف بيانات تشغيل.
- تم استبعاد SQL التاريخي من هذه الحزمة؛ لا تعِد تشغيل أي نسخة قديمة.
- لا تفعيل ضمان على العميل مباشرة، ولا تعديل/حذف تفعيل قائم.
- لا تغيير السيريال أو تاريخه خارج RPC مصمم ومختبر.
- لا تسجيل `printed` بدون دليل من تكامل طباعة فيزيائي معتمد.
- لا بيانات seed للعلامات أو الموديلات أو BOM أو خطوط التصنيع إلا من مصدر معتمد.

## التحقق قبل التنفيذ
1. سجل snapshot للمخطط الحي ونسخة احتياطية قابلة للاستعادة.
2. قارن الجداول والتريجرات والدوال والسياسات والـbuckets والامتيازات قبل/بعد على مشروع تجريبي فارغ.
3. افحص functions search_path وSECURITY DEFINER وgrants وRLS recursive behavior.
4. اختبر حسابًا مستقلًا لكل دور مع positive/negative cases.
5. اعتمد قرار الصلاحيات وحالات الاستبدال كتابةً قبل التنفيذ على الإنتاج.
