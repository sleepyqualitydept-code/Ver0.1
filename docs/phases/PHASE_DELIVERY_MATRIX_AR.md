# خريطة المراحل وبوابات القبول — v1.6

| المجال | مخرجات الحزمة | الحالة الحالية | بوابة القبول المتبقية |
|---|---|---|---|
| المرجعية والمتطلبات | SSoT الأصلية، المخططات التشغيلية/التصنيع/الخدمة وسجل القرارات | محفوظة؛ SSoT لم تعدل | حسم التناقضات التجارية فقط عبر قرار منفصل موثق |

| الإنتاج والدفعات | production orders, lines, batches | منطق الواجهة وRPC للتسلسل موجودان | اختبار انتقالات الحالة ودقة التتبع بمشروع تجريبي |
| السيريالات | إنشاء ذري عبر `generate_serials` وسجل تاريخي | RPC مقترح؛ الكتابات المباشرة ممنوعة | تأكيد قواعد الحالات والاستبدال واختبار duplicate/concurrency |

## ترتيب العمل التالي
1. تنزيل الحزمة وفكها في مجلد منفصل، مع الاحتفاظ بنسخة من المستودع الحالي.
2. رفع هذه الحزمة مرة واحدة إلى GitHub بعد معاينة قائمة الملفات فقط؛ لا حاجة لإرسالها للمحادثة مرة أخرى لإعادة نفس التدقيق.
3. تشغيل GitHub Actions أو `npm ci` + `npm run verify:release` + `npm run typecheck` + `npm run build` ومراجعة النتيجة.
4. تجهيز مشروع Supabase تجريبي فارغ، فحص snapshot/permissions، ثم تطبيق SQL فقط بعد مراجعة مستقلة وموافقة صريحة. لا تستخدم SQL التاريخي.
5. اختبارات role-by-role وقواعد الضمان والاستبدال، ثم اختبار طباعة فيزيائية. لا تنقل بيانات العملاء الحقيقية إلى التجربة.
