## 4. طريقة إعادة البناء

1. فُك خط الأساس أولًا بوصفه شجرة المصدر الأساسية.
2. طُبقت طبقة التكامل المقارنة فوق هذه الشجرة، مع الحفاظ على كل مسارات خط الأساس.
3. أُضيف هذا المخطط المعماري الجديد بصيغتي Markdown وDOCX إلى مجلد المراجع.
4. أزيل مبدل الدور التجريبي في `src/App.tsx`، وأزيلت دالته `switchRoleDebug` من `src/context/AuthContext.tsx`؛ الهدف منع تزوير الدور المعروض داخل حالة العميل. هذا التصحيح لا يثبت صحة سياسات RLS على Supabase.
5. حُدّثت ملفات التعليمات وحالة التكامل لتعكس أن الهدف بيئة جديدة معزولة، ولتحذر من تنفيذ SQL التاريخي تلقائيًا.
6. صُحح فحص قاعدة البيانات داخل التطبيق: سُمّي الفحص بوضوح فحصًا للجداول الأساسية الستة (`hasCoreTables`) بدل الادعاء بأن المخطط كله منشور، وأزيلت أرقام ثابتة مضللة مثل `26/26` و`8/8` و`4/4`.
7. أُزيلت تعليمات الواجهة التي كانت تطلب تشغيل `schema.sql`/`supabase-schema.sql` مباشرة، واستبدلت برسالة مراجعة آمنة تمنع التنفيذ التلقائي وتطلب فحص المخطط والنسخة الاحتياطية والموافقة أولًا.
