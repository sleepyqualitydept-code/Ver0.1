# تقرير تدقيق نهائي — مقاسات القوالب ومسار الطباعة — Sleepee Candidate v1.4

**الحالة:** حزمة محسنة للمراجعة؛ لا تعتبر إصدار إنتاج معتمدًا.

## ما تم التحقق منه وتعديله

- توحيد التحقق من أن العرض والارتفاع أعداد صحيحة موجبة بالمليمتر، وأن هندسة كل عنصر صالحة وتقع داخل حدود اللوحة قبل الحفظ/النشر/استعادة الإصدار/حل القالب للطباعة.
- التخطيط الافتراضي يتناسب مع أبعاد القالب بدل الاعتماد على لوحة 100 مم ثابتة.
- دعم المقاسات القياسية 100×50 و100×80 و100×100، بالإضافة إلى أبعاد مخصصة موجبة.
- منع اختيار قالب تلقائيًا عند إنشاء أمر طباعة؛ يجب اختيار قالب نشط ومنشور صراحة.
- يتحقق مسار أمر الطباعة من تطابق فئة القالب مع فئة الدفعة، ويحفظ لقطة ثابتة من أبعاد القالب وعناصره وإصداره داخل بيانات أمر الطباعة.
- عند تغيير الدفعة في نافذة إنشاء أمر الطباعة، تتم إزالة اختيار القالب السابق لإجبار المستخدم على إعادة اختياره ليتوافق مع الدفعة الجديدة.
- أضيفت معاينة هندسية مبسطة للقالب المختار داخل نافذة الطباعة. هذه معاينة مواقع/حدود العناصر فقط، وليست رندرًا للباركود أو شهادة للطباعة الفعلية.
- تم تقوية وضع العناصر يدويًا وتوزيعها لتقليل احتمال خروجها عن اللوحة؛ تحقق API قبل الحفظ هو الحارس النهائي.
- إعادة الطباعة لا تسجل نجاحًا مزيفًا: تتطلب وجود حدث طباعة أصلي ولقطة قالب محفوظة، ثم تنشئ أمرًا معلقًا.
- `executePrint` يبقى مغلقًا بأمان حتى استكمال رندر قالب إلى صيغة الطباعة وربط Browser Print واختبار Zebra ZD220 فعليًا. لا يحول الأمر إلى Printed ولا يسجل تاريخ طباعة نجاحًا دون تحقق حقيقي.

## الاختبارات والقيود

- فحص سلامة ZIP: سيتم إجراؤه عند إنشاء الحزمة.
- فحص نحوي TypeScript/TSX: يتعذر تشغيل TypeScript الكامل دون تثبيت تبعيات المشروع.
- `npm run build` و`npm run lint`: لم يمكن إثبات نجاحهما في هذه البيئة لأن تنزيل التبعيات انتهى بمهلة. لا تدّعي هذه الحزمة نجاحهما.
- الاختبار المادي على Zebra ZD220 وBrowser Print: لم يُنفذ. مسار الطباعة الحقيقي ما زال يفشل بأمان ولا يدّعي اكتمال الطباعة.
- قاعدة Supabase الحية أو أي Migration: لم يتم تعديلها أو اختبارها ضمن هذه المهمة.

## قبل الإنتاج

1. بعد توفير بيئة Node متصلة، نفّذ `npm ci` عند وجود lockfile أو `npm install` لإنشاء lockfile معتمد ثم راجع التغييرات.
2. نفّذ `npm run build` و`npm run lint` واحفظ مخرجاتها.
3. اعمل اختبار متصفح للقوالب القياسية والمخصصة، وتأكد من حدود العناصر والمعاينة.
4. استكمل رندر ZPL/Browser Print واختبر الطباعة المادية ومقاس الوسيط ومعايرة الطابعة.
5. لا تنفذ migrations قديمة أو تأسيسية قبل إقرار مخطط قاعدة البيانات والأمان بشكل منفصل.
