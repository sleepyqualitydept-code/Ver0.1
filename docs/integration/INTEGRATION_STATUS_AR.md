- **المخطط الجديد:** `docs/reference/Sleepee_Architecture_Development_Blueprint_v1.0_DRAFT_AR.md`

## ما تم في إعادة البناء

1. مقارنة خط أساس المراحل 10–18 مع حزمة التكامل: 108 ملفات في الأساس؛ لا توجد ملفات أساس مفقودة من حزمة التكامل السابقة؛ 26 ملفًا إضافيًا؛ 15 ملفًا مشتركًا مختلف المحتوى.
2. تجهيز النسخة النهائية للحزمة على أساس ترتيب: استخراج خط الأساس أولًا، ثم تطبيق طبقة التكامل، ثم إضافة المخطط المعماري وسجل المصالحة.
3. إنشاء مخطط معماري/خطة بناء عربية بصيغتي Markdown وDOCX لتُقرأ أولًا في Google AI Studio.
4. إزالة واجهة تبديل الدور في `src/App.tsx` ودالة تغيير الدور المحلي في `src/context/AuthContext.tsx` حتى لا يستطيع المستخدم تغيير الدور المعروض في متصفح الواجهة كأنه دور مصدق.
5. الاحتفاظ بترحيل هندسة التصنيع المقترح داخل `docs/proposed-migrations/` خارج مجلد الترحيلات النشطة.

## تغييرات المصدر المعروفة

- طبقة التكامل تتضمن تعديل التنقل ومقاسات الملصقات وإرشاد الإنتاج وواجهات هندسة التصنيع/BOM/Routing وتصحيحات واجهة التحقق والطباعة، كما هو موثق في `PHASE_10_18_RELEASE_NOTES.md`.
- هذه النسخة تزيل مبدل الدور المحلي من واجهة المستخدم. لم تتغير صلاحيات قاعدة البيانات أو أسماء الأدوار في SQL نتيجة لهذا التعديل.
- لم يتم تعديل المرجعية الأصلية أو تشغيل أي SQL.

## المتبقي قبل البناء في Google AI Studio

1. إنشاء مستودع GitHub خاص جديد ورفع محتويات الحزمة (وليس ZIP واحدًا داخل المستودع)، ثم تثبيت الفرع وCommit SHA.
2. فتح المخطط المعماري أولًا في مساحة Google AI Studio الجديدة، ومطالبة الأداة بتقديم تقرير جرد وفجوات قبل أي تعديلات إضافية.
3. إنشاء مشروع Supabase معزول جديد. لا تنقل بيانات حساسة من النظام القديم.
4. تدقيق وبناء خطة تأسيس schema وترحيلات آمنة؛ لا تستخدم SQL الأرشيف أو الـUnified Migration التاريخي تلقائيًا.
5. ضبط التبعيات والـlockfile في بيئة متصلة، ثم تشغيل build/lint واختبارات التدفقات.
6. اختبار Phase 09 وRLS/RPC/الخصوصية والطباعة الفعلية، وإرفاق الأدلة قبل إصدار معتمد.

**النتيجة:** هذه نسخة إعادة بناء منظمة وجاهزة للمراجعة كحزمة مصدر، وليست نسخة تشغيل معتمدة أو متصلة ببيئة Supabase.
