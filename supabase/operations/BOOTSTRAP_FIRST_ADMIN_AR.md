# تعيين أول Administrator في مشروع Supabase الجديد

هذا الإجراء اليدوي مطلوب مرة واحدة فقط بعد اعتماد ونشر الملفات 001 و002 و003 على **مشروع جديد تمت مراجعته**. لا توجد هوية مالك/بريد/UUID مفترضة داخل الحزمة، ولا يتم إنشاء مسؤول افتراضي.

1. افتح **Supabase Dashboard → Authentication → Users** وأنشئ المستخدم الأول من واجهة Auth، ثم انسخ UUID الخاص به.
2. افتح SQL Editor بصلاحيات مالك قاعدة البيانات. انسخ قالب `BOOTSTRAP_FIRST_ADMIN_TEMPLATE.sql` إلى محرر مؤقت، واستبدل `null` في `v_owner_user_id` بــ`'UUID_FROM_AUTH_USERS'::uuid` بعد التحقق يدويًا من الهوية.
3. اقرأ فحوص الأمان داخل القالب. يجب ألا يوجد Administrator سابق، ويجب أن يكون المستخدم موجودًا ولديه profile أنشأه trigger.
4. نفّذ القالب مرة واحدة بعد مراجعة UUID؛ ثم سجّل الدخول بهذا الحساب وعيّن أدوار بقية المستخدمين من واجهة إدارة المستخدمين.

القالب لا ينشئ مستخدم Auth ولا يعبئ بيانات تجارية، ويتوقف إذا لم تُملأ الهوية أو وجد Administrator سابق. لا تشغله على مشروع قائم قبل مراجعة مالك النظام والنسخ الاحتياطي. لا تضف UUID أو البريد إلى Git.
